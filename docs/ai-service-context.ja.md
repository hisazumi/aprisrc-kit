# AI向け技術メモ：APRISRC Kitのサービス開発

[English](ai-service-context.md)

このメモは**現在のソースファイルと一緒に**添付してください。
完全なAPI仕様でも、AIがリポジトリを読んだ証拠でもありません。
人向けの作業手順は[AIと一緒にサービスのコードを書く](ai-assisted-development.ja.md)にあります。

## 一緒に渡すファイル

同じ作業環境の版を使い、関連する未コミットの変更も含めます。

| ファイル | 役割 |
| --- | --- |
| `apps/pwa/src/missions/api.ts` | mission・context・roverの型定義の正本 |
| `apps/pwa/src/missions/index.ts` | 現在の登録一覧とexport |
| `apps/pwa/src/protocol.ts` | 観測・姿勢の型。必要ならimport先も読む |
| `apps/pwa/src/config/index.ts` | 設定の型とexport。必要ならimport先も読む |
| 変更するmissionとそのテスト | 現在の動作と実装パターン |
| `apps/pwa/src/missions/challengerStarter.ts`とそのテスト | 新規missionの既存参照実装 |
| `apps/pwa/package.json` | 利用できる依存関係と確認コマンド |

missionが実際に利用する補助モジュール、関連する設定、必要に応じて`docs/mission-api.md`や
`docs/adding-actions.md`を加えます。専用画面なら対象コンポーネント、呼び出し元、テストも
渡します。依存先が不足していたら推測せず、そのファイルを求めてください。認証情報は求めません。

## 構成と責務

APRISはカンファレンス、APRISRCはそのロボットチャレンジ、APRISRC Kitはサービス試作の基盤です。
サービスは参加者が設計します。サンプルは指定解や競技規則ではありません。

ブラウザの観測 → mission・サービスの状態と判断 → `ServiceRover`
→ サーバーの操作権・安全管理 → Simulatorまたは実機Adapter、という構成です。

通常はmissionと設定を追加・変更し、`missions/index.ts`へ登録します。
`missions/api.ts`、protocol、通信、Adapter、安全機構、ファームウェアは基盤側の管理です。
生成コードをコンパイルするためだけに変更しないでください。公開APIで実現できない場合は、
不足する機能を説明し、別途レビューする基盤変更として提案します。黙って抽象化を追加しません。

## 保持するAPIの意味

添付した型と実装を確認してください。以下は型定義の代用品ではありません。

- `defineMission`がmissionを定義し、`run(context, input?)`が動作を実装します。
  `script`は画面表示用の概要で、実行コードではありません。
- `move`は符号付き距離m、任意指定の速度m/sです。`turn`は符号付き角度degree（正が左）、
  任意指定の角速度rad/sです。`Pose.yaw`と連続指令の角速度はdegreeではなくrad系です。
- bounded move/turnのPromiseは動作完了を表し、失敗・キャンセル時はrejectします。
  完了前に到着を報告しません。`stop()`も停止確認不能ならrejectし得ます。
  それを握りつぶして成功と報告してはいけません。
- `setVelocity`は任意APIで、すべての実機が対応するわけではありません。
  Promiseは送信の完了であり、実動作の完了ではありません。使える既存の追従helperを優先し、
  サンプル内に新しいモーター制御ループを作らないでください。
- `getPose`は推定値で、取得不能な場合があります。観測座標、マーカー補正、
  画像内の人物枠の幅を、メートル単位の距離と混同しません。
- 観測の購読は解除関数を返します。完了・キャンセル・エラー時に解除し、
  listenerやtimerの重複、複数動作の同時実行を避けます。
- `AbortSignal`を尊重し、待機や繰り返しに終了条件を設けます。
  対象喪失・古い観測・任意APIの未対応を明示的に扱います。再接続・非常停止後に
  自動再開しません。操作権と走行同意は呼び出し元UIに管理させます。
- `say()`はブラウザへの発話要求で、聞こえる音声の終了まで待ちません。
  `report()`は進行表示を更新するもので、実機状態を変えるものではありません。

## 自然言語のトリガ

任意の`trigger`にはintent、description、examples、keywords、responseがあります。
mission IDとintentは一意にし、既存登録を残してください。命名と予約intentは
`adding-actions.md`を参照します。ローカルrulesはキーワードの部分文字列一致、
LLMは登録済みintentの選択を担当し、任意の実行コードを生成するものではありません。
開発相談のチャットAIと、実行時にアプリが呼ぶLLMは別です。
missionの編集だけなら実行時LLMのキーは不要です。キーを使う場合はサーバー側で管理します。

登録は`/lab`のmissionとintent一覧に反映されます。専用の`/app`フローやPlaygroundの
サンプルは別途統合が必要で、自動追加されると説明してはいけません。
変更範囲への明示的な合意なく、依存関係追加、公開仕様変更、安全条件の緩和を行いません。

## 回答の形式

意図する動作を短く説明し、変更する正確なパス、小さくレビューできる差分、確認コマンドと
観測すべき結果を示してください。既存の実装・テストに合わせ、不足するソースは質問します。
コードを読んだこと、実行したテスト、提案した確認、Simulatorの観測、実機での確認を区別します。
模擬テストだけで実機が動いたと主張してはいけません。
