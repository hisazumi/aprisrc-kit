# 最小の運用コンソール

[English（正本）](operator-console.md) · [Simulator接続](simulator-integration.ja.md)

既存の `RunnerPort` と共通 `RoverRuntime` に、ローカルの `/console` を接続した。
backendは平面Simulator固定。操作権・移動禁止・受け渡しguard・停止待ち・位置・
最近の操作結果を表示する。ブラウザは既存の移動契約で有限のmove／turnを要求し、
モータコマンドは直接送らない。

## 起動と操作

```sh
uv sync --directory apps/server --frozen
uv run --directory apps/server python -m apris_server.operator_console
```

端末に表示されたURLを開く。`127.0.0.1:8766/console` のfragmentに起動ごとのtokenを含む。
画面はfragmentを消し、tokenをタブのsession storageに保持する。
サーバを再起動するとtokenとcontrol epochが変わるため、新しく表示されたURLを開く。
外部ホストでの待受けや実機backendを選ぶ起動オプションはない。

1. 「操作権を取得」。初期状態は移動禁止。
2. 人の退避確認にチェックし、「明示復帰」。これだけでは移動しない。
3. 「試験runを開始」。前進には、合成の前方安全観測を送るチェックも必要。
   「4 cm 前進」「0.1 rad 左旋回」で動作を試す。
4. 移動完了後に「受け渡しを開始」。移動が禁止される。
   完了には改めて退避確認が必要。guard IDが変わると確認チェックはリセットされる。
5. 「停止・移動禁止」は受け渡し中も有効。runを失効し、移動禁止を保持する。
   停止確認後、現在のguardに対する退避確認と明示復帰を行う。
   動かすには新しいrunと移動要求が必要。
6. 受け渡し中に再読込み・画面を閉じる操作を試す。guardは残る。
   運用者lease失効後は、操作権の再取得と明示復帰が必要で、移動は再送しない。

画面は100 ms周期で状態取得を試み、非表示になっても生存確認を停止しない。
明示取得した運用者のlease（Simulatorコンソールでは3秒）と、試験runのlease・移動TTLをそれぞれ既存契約で更新する。
**状態を読むだけではleaseを更新しない。** 画面を閉じる・通信が途切れると更新が止まる。
これらは試験用の期限で、ブラウザの抑制や遅いPCでは操作権が失効することがある。
最終的な操作権はPythonが持つ。この画面は運用者兼試験driverであり、通常のサービス画面とは別。

HTTP側ではHost・Origin・ランダムなbearer token・64 KiBのbody上限を確認する。
静的画面にはCSPを適用し、外部依存はない。利用者・役割のアカウント管理は未実装なので、
proxy経由で公開したり、本番のネットワーク認証として扱ったりしない。
前方観測は明示したSimulator入力で、実機の安全情報ではない。
件数制限付きの操作結果表示は診断用で、永続的なtrace記録ではない。

## 検証と残課題

HTTP統合試験4件で、token／Origin／Host／body制限、明示復帰、古いguardへの応答拒否、
閲覧だけの再接続とlease失効、guard保持、再起動epoch、移動中のglobal stop、復帰後の再送なしを確認。
DOM試験2件では実際のHTML／JavaScriptを使い、閲覧のみの初期状態、毎回の退避確認、
非表示中の更新継続（後続修正）、再起動後に操作権を自動取得しないことを確認した。

ローカルでserver全397件、Node全140件、厳密なTypeScript、Ruffが成功。
既存のSimulator停止試験は浮動小数点の完全一致で失敗することがあったため、
停止後の数値誤差として絶対誤差1e-12だけを許容する形に修正した。
実Chromeでの画面確認はこの環境ではheadlessプロセスの起動時に失敗したため未完了。
DOM・HTTPの動作は検証したが、実ブラウザの表示確認は残る。
CIにも組み込んだが、ここでの件数はローカル検証の結果。

今回はEの運用者側の実装で、E全体の合格を意味しない。現行PWAの起動経路は変更していない。
コンソールは一つのSimulator runtimeを所有し、既に動いている `runFakeService` の
子プロセスや実機へ接続するものではない。
学生サービスの一般的な質問画面、runの寿命と独立した通常 `/app` の再接続、
この継続稼働する操作権へのNode host接続が次の統合作業となる。
guardはメモリ内のため、再起動時には明示復帰を要求するが、それ自体は退避済みの証拠ではない。
guardの永続化と実機の検証は追加していない。

後続のNode接続と質問画面は[運用runtimeへのサービス接続](connected-service.ja.md)を参照。
