# 運用runtimeへのサービス接続

[English（正本）](connected-service.md) · [運用コンソール](operator-console.ja.md)

現在の推奨起動手順は[コンソールからの開始・再実行](managed-service.ja.md)。以下のNode手動起動は開発用として残す。
Node hostを、起動済みのPython運用runtimeへ接続した。二つ目のSimulatorは起動しない。
`runConsoleService` がHTTP通信を提供し、既存 `runFakeService` のactivity runner・
移動facade・質問・終了処理を共用する。学生の `myService` は変更していない。
従来の単独fake／Simulatorデモも維持する。

## 起動と操作

リポジトリのrootで実行する。

```sh
uv sync --directory apps/server --frozen
uv run --directory apps/server python -m apris_server.operator_console
```

表示されたコンソールURLを開き、操作権を取得し、人の退避確認と明示復帰を行う。
合成の前方CLEAR観測も有効にする。**手動の試験runは開始しない。** Node接続時にrunを作る。
コンソールは開いたままにする。別タブのサービス画面へ切り替えても生存確認は続ける。

別の端末で、表示URLの `#` より後ろのtokenを指定する。

```sh
export APRIS_CONSOLE_TOKEN='ここに今回のtokenを貼り付ける'
node apps/runner-prototype/console-service.ts
```

表示された `/app` URLを、別タブまたは別ウィンドウで開く。
合成の人物検出入力、既存サービスの質問、積載確認に回答する。
積載の回答だけではguardは解除されない。**コンソール側で**退避確認にチェックし、
受け渡しを完了する。Nodeは回答と運用者の解除の両方を待つ。

接続デモの追従は、合成の短い移動後に停止し、到着回答を待つ形に変更した。
移動中に到着を押した場合は取消・停止を確認する。停止後なら急いで押す必要はない。
移動・停止期限は延長せず、回答待ちを移動から分離する。
人物入力・通常の質問・積載・到着確認は、leaseが健全ならhost全体の2分の予算内で待機できる。
これは実際の人物追跡ではなく、対話を試すための停止待機付きデモ。
単独fakeデモの追従動作は従来どおり。

サービス画面は未開始・実行中・正常終了・中断・失敗を区別する。
終了後は「質問を待っています」と表示せず、結果と失敗理由を残す。
Nodeが結果を報告せずに終了した場合も、run失効を正常終了とは扱わず中断と表示する。
結果はrun epochを照合し、古いrunの報告や結果の上書きを拒否する。

正常終了はrunを閉じ、Nodeの接続を終了する。Pythonと運用コンソールは継続する。
停止・lease喪失・サーバ再起動・通信断で自動復帰や移動再送はしない。
サービス画面の再読込みだけでは運用者・runのleaseを更新も失効もさせない。
接続したrunの更新はNode、運用者の更新はコンソールがそれぞれ担当する。
サービス接続中はコンソールの手動移動・guard取得を無効化し、全体停止・run終了・退避確認は使える。

## 質問と通信

質問brokerは同時に一問、質問IDと案内文はそれぞれ最大128件。
回答は現在のview ID・run epoch・question ID・選択肢に一致する必要がある。
新しいサービス画面を開くと、古い画面からの回答を拒否するがrunは取消しない。
重複回答・古い回答・余分なフィールドも拒否する。`/app` から退避済みの宣言は送らない。
停止保持が必要な質問は、Pythonのguardが解除されるまで回答を消費できない。
画面の文字列はHTMLとして解釈せず、テキストとして表示する。

HTTPはコンソールのloopback・Origin・token検証と既存の型付き契約を使う。
要求timeoutは1秒、未完了要求は32件まで、応答サイズは256 KiBを検査する。
128件の連番付きイベントをpollし、取りこぼしや再起動では接続を失敗させる。
移動要求は再送しない。移動完了直後の更新エラーが先に届く競合に対しては、
エラー通知前に先行するイベントを読み出す。MotionClientのscope・generation照合は維持する。

デモの各画面とNodeは同じローカルtokenを共有する。画面の責務は分けたが、
**役割別のネットワーク認証ではなく**、tokenを持つ利用者は別のローカルAPIも呼び出せる。
Simulatorのみを有効化し、現行PWA・実機の起動経路は変更していない。
人物・前方入力も合成であり、認識機能ではない。

## 検証

実際のNode・Python・HTTPを使い、既存学生サービスの正常終了、オドメトリ変位、最終速度ゼロ、
サービス画面の再接続と古い回答の拒否、重複回答の拒否、回答と独立したguard解除を検証した。
Nodeが生きている間の運用者lease切れと、運用者が在席中のNodeプロセス強制終了も試し、
run失効・guard保持を確認した。完了通知と遅れた更新エラーの順序、イベント欠落も回帰試験にした。
HTTP検証とDOM試験では、質問上限・選択肢検証・実際のサービス画面の回答照合とテキスト表示を確認する。

初回接続時はPython全398件・Node全145件が成功。到着待ち・終了表示の修正後は、
Node全146件・運用APIのPython試験6件・厳密なTypeScript・Ruffが成功。
到着回答を1.8秒遅らせ、停止中の位置が変わらず、その後正常終了する回帰試験を追加した。
実プロセス・HTTP・DOMの検証であり、実ブラウザの表示確認や実機停止の認定ではない。
CIも新規テストを実行する構成だが、ここではローカル結果を記録する。
guard永続化、役割ごとの認証、長時間追従、既存PWAへの本統合は残課題。

## ブラウザ用leaseの見直し

画面分離は維持し、コンソールの非表示を離脱とみなす処理を削除した。
このSimulator運用サーバのoperator leaseだけを3秒に変更。
Nodeのrun leaseは400 ms、移動command TTLは250 msのままとする。
タブ切替は権限失効の理由にせず、明示停止または更新の途絶を停止条件にする。
生存確認は運用者が物理的に在席している証明ではなく、許可済み接続の生存を示す。
ブラウザが長時間凍結・休止した場合には3秒で失効する。停止後の自動復帰は行わない。
初期のstandalone fake portの期限は変更していない。

変更後はNode全146件と運用APIのPython7件、TypeScript、Ruffが成功。
非表示中のheartbeat、1秒間隔更新、更新途絶でのguard保持、独立した250 ms TTL停止を確認した。
