# 実機Playground

[English](hardware-playground.md)

ソフトウェアのプロトタイプです。模擬ライブ入力によるテストと、WebSocketアダプターの実機未接続画面を
確認しました。このPlayground UIでの実機走行は未検証です。以前の実機追従の確認とは区別してください。

モードはサーバーのアダプターで決まります。ブラウザでアダプターを変更したり、モーターへ直接接続したりしません。
Simulatorではシーン操作、websocket_roverではライブカメラ観測と実機状態を表示します。
factory_httpは対象外です。マーカー値は観察できますが、実機でのマーカー案内開始は今回は無効です。

## 実機があるときの手順

1. [UGV02セルフテスト](../hardware/ugv02-self-test.md)と
   [WebSocketファーム接続](../hardware/ugv02-websocket-firmware.md)で準備します。
   ID・tokenを揃え、private LANを使います。tokenをURLやGitに入れないでください。
2. 既存のAPRIS_ADAPTER=websocket_rover設定でサーバーを起動します。
   ローバーに載せたスマホで`/lab?sample=follow`を開きます。LANアクセスにはHTTPSが必要です。
   [HTTPS設定](../local-https.md)を参照してください。
3. 適切なカメラでStart visionを押し、カメラ権限は自分で許可します。
   人が認識され、accepted camera eventが出ることを確認します。
4. 実機接続と新しい状態を確認してAcquire controlを押します。
   通路が空いた監督下の試験場所でConfirm clear path · 30 sを押します。
   自動障害物認識ではなく、運転者の確認です。サーバーの前方状態がCLEARになる必要があります。
5. 最初は`/lab?sample=greeting`でStart greetingを押し、浮かせた車輪でbounded旋回と停止を確認します。
   停止後にFollow helperへ切り替え、入力と通路を確認し直して明示的にFollow meを押します。
   浮かせた試験が成功してから短い床走行を試し、停止できる運転者が監督してください。
6. Stopでサービス中止、Disable motionで通路許可取消、Emergency stopで停止を保持します。

カメラ・人・実機の再接続だけで自動開始しません。通路確認は30秒で失効し、明示的に更新できます。
カメラ停止・故障、人の喪失・古い観測、古い実機状態、接続断、制御権喪失、非常停止、前方がCLEAR以外、
許可期限切れでは開始可否を解除して実行中のサービスを中止します。入力喪失後は通路を再確認して開始し直します。
許可のheartbeatは既存のサーバー側leaseを使い、ブラウザ停止時に維持しません。
無人運転や一般的な障害物回避には使わないでください。

## 可視化するもの

- ライブ映像と既存の上半身認識枠。
- サーバーが受理したcameraの人物状態・信頼度・観測経過時間・方位・画像内の幅。
- cameraのマーカーID・状態・観測経過時間・相対x/y。今回はQR枠の映像への重畳はしません。
- サーバーの前方安全状態と実機の推定姿勢。
- 直近12秒の速度・角速度の実機推定値。外部計測ではなく、状態が来ないことも停止の証拠にはなりません。
- Simulatorと同じサービスコードと、報告された判断箇所の強調。
- 時刻付きの移動・旋回要求、完了・失敗、停止理由。モーター指令波形や命令単位のデバッガではありません。
- 折りたたみ欄のサーバー観測と拒否理由。

実機サービスにはサーバーのcameraイベントだけを渡します。録画・manual・scenario・replayは開始に使いません。
観測は引き続きサーバーで検証されます。実機モードではSimulatorの位置リセット、仮想CLEAR、仮想人・マーカーの
注入、シーン編集を使いません。runtimeとファームの安全機構は維持します。

## 実機がない間

[Simulator実習](playground-workshop.ja.md)は引き続き利用できます。テストではカメラ準備状態・受理観測・実機状態・
動作結果を模擬して、開始条件、入力の選別、中止、許可期限切れを確認します。
認識精度、Wi-Fi遅延、車輪の向き、滑らかさ、停止距離の保証ではありません。実機で上記の手順を検証します。
未接続のWebSocketサーバーでも画面は表示されますが、サービス開始・通路許可は無効です。
接続したふりの仮想実機ではありません。

フロントエンドの確認は`npm test`、`npm run typecheck`、`npm run build`です。
