# 監督付き低速の試験モード

[English](ironx-supervised.md)

近くの監督者が機体を止められる運用を前提にした、iron-X専用の明示選択モードです。
通常設定と他機種は変更しません。監督付き追従は実機確認済みですが、通信断後の停止時間の
実測は未実施です。学生の試行も監督付きで行ってください。

## 設定

`APRIS_IRONX_PROFILE=supervised_low_speed`を選ぶと、次の設定になります。

- PC runtimeは呼び出し元の速度指令TTLを明示的に8秒へ置き換えます（通常のネットワーク上限200ms）。
- 機体側mailbox上限8秒、nonce寿命8秒、操作権10秒。
- ネットワーク越しの観測の古さは3秒まで、状態取得・走行応答待ちは3秒。
- 速度上限は0.15m/s・0.2rad/sのままです。

機体側のcommand bridgeが期限に達した指令をゼロ出力にします。同じmailboxを読み続けても
期限は延びません。通信待ち時間は元の指令予算から差し引き、期限切れや停止で無効になった
指令は再送しません。新しい指令が来なければ最後の指令の8秒予算でゼロ出力になります。
0.15m/sで8秒なら最大約1.2mに停止までの動きを加えた距離になります。
これはソフトウェアのゼロ出力期限であり、ROS・OS・シリアル・モータードライバー自体の
故障時に物理停止を保証するものではありません。

機体内のセンサー・bridgeの鮮度確認は変更しません。人物喪失、障害物、停止操作、切断などで
より早く止まることはあります。本当の通信障害時の再解除要求は維持し、再接続だけで再開しません。
通信経由の非常停止も通信到達が必要なので、物理停止・電源操作を可能にしておいてください。

## 起動と解除

サービスを停止し、物理停止を確認してからPCと機体を同じ版に更新します。Windows PCでは
Kit起動前に次を設定します。

```powershell
$env:APRIS_IRONX_PROFILE = "supervised_low_speed"
```

機体のgatewayとcommand bridgeの**両方の起動環境**に次を設定して再起動します。
macOS/LinuxのPCでも同じ構文です。

```sh
export APRIS_IRONX_PROFILE=supervised_low_speed
```

既存の分離したROS構成を使います。driver・telemetry bridgeは変更せず、gatewayは
`--start-estopped`で起動します。PC・gateway・command bridgeの設定が違えば走行を拒否します。
`/api/status`の`config.effective_safety_limits`で`ironx_profile`が
`supervised_low_speed`、`motion_ttl_ms`が8000になったことを確認します。
既存の設定ハッシュだけではこの環境変数のモードを識別できません。

戻す際は停止確認後、3か所とも`APRIS_IRONX_PROFILE=standard`にして再起動します。
片側だけの変更や、走行中の切替はしないでください。

## 検証範囲

2026-11-02、iron-Xで操作者から良好な追従の報告がありました。観測区間では走行指令310件が
正常応答し、指令失敗・停止確認失敗・非常停止への移行はありませんでした。応答中央値約11ms、
最大約103ms、最後の計測速度はほぼゼロでした。大きな遅延や意図的な通信断は発生していないため、
8秒watchdogや10秒以内の物理停止の検証にはなりません。

実機なしの試験では、本物のgateway・network adapter・runtimeをループバック通信で動かし、
遅延、設定不一致、mailbox再読、期限停止、センサー喪失、非常停止を検証します。
実機での通信断試験の代わりにはなりません。学生へ渡す前に監督付きで短距離走行を行い、
新しい指令を途絶させて、合意した10秒以内に実際に止まることを測定してください。
それまでは通信断時の停止動作を実機検証済みとは扱いません。
