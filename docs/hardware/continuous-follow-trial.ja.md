# 連続追従の実機試験準備（実験的）

[English (canonical)](continuous-follow-trial.md)

現時点はソフトウェアの準備のみで、iron-Xの連続追従は実機未検証です。
Simulatorでは実カメラの揺れ、Wi-Fi遅延、制動性能まで評価できません。

Simulatorは上限0.25 m/s・距離ゲイン0.8の連続P制御を使います。
実機は既定で従来の距離指定方式のままです。明示的に有効化できるのは
`ironx_network`だけで、UGV02・同一ホストiron-Xは変更しません。

PWA開発サーバーを起動する前に設定します。

```sh
export VITE_IRONX_CONTINUOUS_FOLLOW=1
```

[PC・iPhoneの既存手順](ironx-follow.ja.md)に従い、PCサーバーは`ironx_network`を使います。
この設定は制御方式を選ぶだけで、走行許可ではありません。開発時はViteを再起動し、
サービス停止中にスマホを再読み込みします。配布版PWAは設定変更後の再ビルドが必要です。

実機プロファイルは前進上限0.15 m/s、距離ゲイン0.6です。
共通の既定値は旋回上限0.2 rad/s、加速度0.12 m/s²、減速度0.3 m/s²、
角加速度0.5 rad/s²です。喪失・故障による停止では通常の加減速制限を迂回します。
サーバーの操作権、前方確認、非常停止、指令有効期限は維持します。
速度APIの応答は送信完了であり実際の動作完了ではありません。物理停止を操作できる状態にします。

操作者の許可後、短い前進追従、左右への追従、人の停止、対象喪失の順に確認します。
指令速度・観測速度・停止距離を記録し、停止を確認する前に最高速度を上げないでください。

戻す場合はサービスを止め、`VITE_IRONX_CONTINUOUS_FOLLOW`を未設定にし、PWAを再起動・
再ビルドしてスマホを再読み込みします。実機は従来のmove/turn追従に戻ります。
再接続だけでサービスを再開しません。ソース設定やソフトウェアテストの成功は、
実機への配備・動作確認を意味しません。

## 学内試験（2026-11-01）

初回は約1.3秒の右旋回出力の後、走行応答のタイムアウトで停止しました。
前進出力はなく、その後の観測速度はほぼゼロに戻りました。追従成功の確認ではありません。
SSH経由の状態取得40回では往復時間の中央値9.75ms、最大106.3msでしたが、
先の250msタイムアウトの原因を特定するものではありません。

PC側の走行応答待ちを最大1秒に分離しました。指令の有効期限200msと
ゲートウェイ操作権の有効期限300msは変更していません。通信が遅ければ停止・中断します。
100ms以上かかった応答は処理名と所要時間を記録します。
停止・操作権返却・切断時の停止確認失敗は、非常停止を保持して`stop_unconfirmed`を通知します。
停止済みと報告したり、クライアントの後処理を例外で中断したりしません。
遅延応答・停止失敗の自動テストは通過しましたが、実機での再確認は必要です。
共用ネットワークではSSHトンネルまたはTLSを使用してください。
