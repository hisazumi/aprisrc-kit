# iron-Xで人追従を試す

[English (canonical)](ironx-follow.md)

任意で有効化するP制御版は[連続追従の実機試験準備](continuous-follow-trial.ja.md)を参照してください。
現時点はソフトウェア準備のみで、以下の実機既定フローは距離指定方式のままです。

監視付きCarry helper試験の入口です。無人自律走行や新規ROS環境構築のガイドではありません。

## どこで何を動かすか

| 機器 | 役割 |
| --- | --- |
| iron-X | ROS driver、telemetry bridge、指令期限付きcommand bridge、認証付きnetwork gateway |
| 学生PC | `APRIS_ADAPTER=ironx_network`のKitサーバー、PWA開発サーバー |
| 車載iPhone | Safariのカメラ認識とサービス画面。観測をPCへ送る |

信頼できる同一LANで、各機器が接続先へ到達できるようにします。
スマホで開くのは**PCのHTTPSアドレス**です。ロボットのアドレスや`localhost`ではありません。
gatewayの平文`ws://`通信とスマホ向けHTTPSは別経路です。

## 動かさずに準備する

1. 実機担当者が[ネットワーク接続](ironx-network.ja.md)を準備します。
   driver、bridge、Node-REDの走行送信者を重複起動しないでください。
2. PCで`ironx_network`を選び、gateway URLと非公開tokenを設定します。
   実機を使わないときの既定はSimulatorのままにします。
3. [HTTPSとスマホの証明書信頼](../local-https.ja.md)を設定します。
   PWA起動時に表示されるポートを使います。通常は5173、HTTPとHTTPSを並行起動する
   場合は5174など別途指定した番号です。証明書の信頼設定は必要です。
4. Safariで`https://<PCのLANアドレス>:<HTTPSポート>/app`を開き、**Carry helper**を選び、
   **Start camera**でカメラを許可します。前方を向くカメラを選び、スマホをしっかり固定し、
   人の上半身が認識されることを確認します。
5. 他のサービス・コンソールを停止して操作権を解放します。前方・左右・後方を空け、
   物理停止・電源を操作できるようにし、動かす前に操作者の許可を得ます。

カメラの準備だけではサービスは始まりません。ボタン操作の追従にはLLM APIキーは不要です。
文字・音声による指示解釈には任意で[rules / OpenAI / Gemini](../assistant-providers.ja.md)を使えます。

## 開始と停止

1. 周囲を確認して **Start service and allow movement** を押します。
   認識した人への接近を含む、監視付き走行の許可です。
2. 人を安定して検出すると接近し、停止して支援を提案します。
3. **Yes, help me**、準備ができたら **Items are loaded** を押すと追従します。
   デモでは実際の荷物はなくても構いません。
4. 上半身がカメラに映るようゆっくり歩きます。Safariを表示し、スマホをロックせず、
   ロボットから目を離さないでください。
5. **Stop**または**We have arrived**で追従を止め、**End service**で停止・操作権解放します。
   必要なら**Emergency stop**を使い、ソフトウェアで止まらなければ物理停止・電源を使います。

Carry helperでは **Allow movement for 30 s** の押し直しは不要です。開始操作で監視付き走行を
許可し、接近・追従中だけ短い期限のclearance heartbeatを更新します。通信断、操作権喪失、
非常停止、画面非表示で許可を取り消します。中断後は明示的に再開し、再接続だけで走行を再開しません。
**Look for the next person**が表示される場合は押して開始画面へ戻り、周囲を再確認してから
**Start service and allow movement**を押します。
Consoleの **Confirm clear path · 30 s** は手動走行専用として残ります。
Mobile ReceptionistとLive Playgroundはそれぞれの許可手順を維持します。
手動確認は障害物認識ではなく、一般的な衝突回避機能はありません。

## 止まったとき

| 表示・状況 | 意味と対応 |
| --- | --- |
| 目標距離に到達 | 正常な待機。サービスが継続中なら人が遠ざかると追従を再開する場合があります。 |
| `person observation stale` / 対象喪失 | 新しい人物観測が途絶えました。画角、照明、ロック・バックグラウンド化、接続を確認します。これらは原因候補で、断定ではありません。サービス終了後は明示的に再開します。 |
| `front_obstacle_unknown` | 新しいclearance heartbeatがありません。許可、操作権、接続を確認し、安全チェックは無効にしません。 |
| `ironx_rearm_required` / 非常停止 | 停止が保持されています。実際の停止と原因を確認してから明示的に解除します。 |
| gateway・bridgeの停止確認失敗 | 担当者による復旧が必要です。解除を連打したり、サーバー再起動を非常停止解除として使ったりしないでください。 |

非常停止を解除するには、実機を確認してから同じPCサーバーの`/console`を開き、
**Acquire control → Clear E-stop**を押します。表示が消えたら**Release control**で操作権を
解放し、`/app`に戻ります。解除だけではサービスは開始しません。解除要求に失敗した場合は
停止を保持します。操作中の他の人から無理に操作権を奪わないでください。

通信障害のログにはRPC名と例外種別を残します。通常の動作キャンセルで停止確認を中断しない
ようにしていますが、確認が期限内に取れない場合の安全停止は維持します。
[運用・ログ](../operations/runbook.md)も参照してください。

## 設定と確認範囲

iron-Xの現在の前後進上限は**0.15 m/s**、旋回上限は**0.2 rad/s**、PC側ネットワーク指令の
有効期限上限は**200 ms**です。追従は0.10 mずつ・0.15 m/s、接近は0.08 mずつ・0.05 m/sを
要求します。短距離では減速するため、これらは指定値・上限であって実測速度ではありません。
